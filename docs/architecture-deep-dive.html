  1. Edge to app — no public load balancer

    Users hit CloudFront (AWS WAF), where Cognito Authorization@Edge gates browser entry: a Lambda@Edge CheckAuth redirects unauthenticated browsers to the Cognito hosted UI (the same adt-app user pool), while /api/* and /health bypass the edge gate and keep the app's own 401 bearer/session auth. The ALB is internal, reached only through a CloudFront VPC origin. The ADT app is FastAPI + SSE on ECS Fargate.

  2. Three distinct auth hops

    App → orchestrator runtime: SigV4 (IAM). Orchestrator → gateway: MCP + OAuth2 bearer — a forwarded user JWT, or service client-credentials for background turns (CUSTOM_JWT authorizer). Gateway → system agents: Cognito M2M OAuth (client credentials); each runtime enforces its own inbound JWT authorizer. Interactive turns additionally carry an app-signed, ≤5-min identity claim verified at each system agent (per-system group policy optional).

  3. Reasoning tiers per task — not one model

    The orchestrator runs on a deep-reasoning tier (cross-system planning, answer synthesis, onboarding schema-mapping escalation), by default Claude Sonnet 5.5. System agents run on a fast task tier (narrow, schema-scoped query composition), by default Claude Haiku 5.5. Tiers differ because reasoning depth trades against cost and latency, and the defaults are measured with the golden eval lane, not assumed.

    Swap without code: role catalog default → deployment env → per-system override → admin page (SSM-backed). Both roles switch live — no redeploy, no re-onboard.

  4. Memory & metadata stores

    AgentCore Memory: 7-day event TTL, per-user namespaces (facts / preferences / summaries); only interactive chat writes. DynamoDB holds self-learning proposals, the prompt library, and dashboard cards. Neptune holds rules — never production data (see slide 2). AgentCore Evaluations continuously samples orchestrator traces (~10%) and scores them with built-in judges — quality telemetry, not a CI gate.

Model catalog footnote: concrete model choices resolve through agents/model_catalog.py — the single source, live-editable from the admin page (role-based defaults, region-resolved inference profiles, per-system overrides). · Edge footnote: all three browser-facing CloudFront distributions (app, ERP dashboard, HighByte UI) carry the standard AWS WAF managed rules and Cognito Authorization@Edge; machine paths (/api/*, /health, HighByte /mcp* /i3x* /data/*) bypass the browser gate and authenticate at the origin.

Default is report-only — capture runs in shadow and answers stay model-authored; annotate (grounding score + zero-evidence block) is the recommended production posture, enforce the opt-in strict gate.

  1. A vocabulary, not a warehouse

    A closed vocabulary of node labels and edge types describes systems, schemas, field meanings, identity rules, join paths, authority, the OT asset hierarchy, and deployment-defined metric definitions — enough to translate identifiers between systems and plan cross-system queries. docs/graph-shape-contract.md is the canonical inventory, and the graph carries its own metamodel (MetaNode / MetaEdge) so drift is visible.

  2. The contract

    No production data ever lands in the graph. Batch numbers, order IDs, and sensor readings stay in the systems of record; the graph tells the orchestrator where and how to fetch them live.

  3. Learning with a human gate

    Query-time discoveries become DynamoDB proposals with confidence scores. Humans accept or decline in the review UI — a user decision always beats the agent (superseded state + version). Only accepted rules reach Neptune, one live node per subject.

  4. Every layer argued, not assumed

    Each design layer carries a written justification and an honest counter-argument in the ADR log — including which layer local dev can't reach (the VPC-private graph) and which exceptions remain open for revisiting.

Backing: Neptune Analytics graph adt (a retained pre-rename resource name — see the glossary) · openCypher via the neptune-graph ExecuteQuery data plane · public_connectivity=False. Proposal store: DynamoDB adt-proposed-mappings (status + subject-key GSIs).

  1. Private OT edge

    The simulated OPC UA servers (Milwaukee · Detroit · Cedar Rapids · Indianapolis) sit in private subnets behind four per-site internal NLBs — nothing internet-facing. The Indianapolis server carries the 5-Axis-Milling-CMX-441 bearing-degradation cycle live (ADR-0083). Endpoint: opc.tcp://<nlb>:26543/UA/ManufacturingServer. Demo connections are unencrypted/anonymous — enable OPC UA message security for production OT.

  2. Unmodified vendor image

    HighByte runs the public Docker Hub image highbyte/intelligence-hub:4.5.3, with no ECR repository or build pipeline. A busybox init container seeds settings onto EFS; app state lives at /usr/local/highbyte/appData.

  3. One shared service port

    MCP + REST + docs share :8885; the UI is on :45245. Health check: /data/doc. The pipeline writes 24 asset models / ~170 assets into IoT SiteWise.

  4. Web access — VPC origins again

    CloudFront carries the standard AWS WAF managed rules and gates the UI paths with Cognito Authorization@Edge (its own highbyte-ui-users pool); it routes the default behavior to the UI origin and the machine paths /mcp* /i3x* /i3X* /data/* — which bypass edge auth and authenticate with a bearer token at the origin — to the shared origin. The internal ALB accepts ingress only from the CloudFront VPC-origin service security group.

Note: the HighByte distribution is protected like the app and ERP-dashboard distributions: AWS WAF managed rules plus Cognito Authorization@Edge on browser paths. The hub runs with ACCEPT_EULA=Y only after the deployer reads and accepts the HighByte EULA (--accept-highbyte-eula, once); the deployer supplies any license via the HighByte UI.

  1. One scheduled Lambda

    EventBridge rate(1 minute) triggers only the simulation orchestrator with {"action":"single_cycle"}. Cleanup is wired to the dashboard's Reset button; seed runs at deploy time. All three are ARM64 container-image Lambdas from ECR.

  2. A real relational surface

    30 tables across 12 schema files span ERP and MES domains — orders, inventory, suppliers, BOMs, production, shipping/financial, mes_*, and simulation bookkeeping — across four simulated sites (Milwaukee · Detroit · Cedar Rapids · Indianapolis). "Orders" resolves to customer_orders.

  3. Auth at the edge, not the ALB

    Cognito login happens at CloudFront via the SAR cloudfront-authorization-at-edge app (v2.3.2, Lambda@Edge check/parse/refresh). The ALB stays internal behind a WAF-protected CloudFront VPC origin.

  4. Ops access without exposure

    The bastion EC2 instance is reachable only through SSM Session Manager — no inbound SSH, no public IP path to the database.

Not the product: this stack exists so the demo has live data — it onboards through the same dynamic path as any customer system (ADR-0030). Flags are not sticky: an environment that should keep the demo data must pass --seed/--simulator on every deploy, or CDK removes the simulator stacks (including the Aurora data).
