  1. ADT application path

    Users reach Amazon CloudFront (AWS WAF; Cognito Authorization@Edge gates browser sign-in, /api/* keeps 401 auth); the ALB is internal — a CloudFront VPC origin. The app: FastAPI + SSE on ECS Fargate. DynamoDB: proposals, prompt library, dashboard cards. Neptune Analytics: the knowledge graph — a VPC-private rules engine (openCypher), never a production-data store.

  2. Bedrock AgentCore — three auth hops, tiers per task

    App → orchestrator: SigV4 (IAM); orchestrator → gateway: MCP + OAuth2 bearer; gateway → system agents: Cognito M2M OAuth. Interactive turns add an app-signed ≤5-min identity claim, verified at each system agent (per-system group policy optional).

    The orchestrator (chat + scheduled briefings) is one of a family of runtimes: onboarding + one per system. Deep-reasoning tier (Claude Sonnet 5.5) for the orchestrator, fast task tier (Claude Haiku 5.5) for agents, both live-switchable catalog defaults. Memory: 7-day event TTL, per-user namespaces. Evaluations: ~10% of traces scored by built-in judges (Faithfulness · Relevance · Correctness) → CloudWatch + the Agents page.

  3. Onboarded systems

    ERP + MES ×3 (Milwaukee · Detroit · Cedar Rapids) on Aurora PostgreSQL; CMMS + PLM on RDS PostgreSQL; IoT SiteWise live reads; HighByte UNS over MCP/HTTPS. Each system gets a schema-scoped agent (per-system model override available).

  4. Open to external agents — AWS Quick

    The gateway is a standard MCP + OAuth2 surface: external agents like AWS Quick consume the same per-system tools with no gateway changes, using Cognito-issued OAuth2 credentials scoped to adt/query. Opt-in --quick-api adds a bridge gateway and an IAM-authorized REST API.

  1. Private OT edge

    The simulated OPC UA servers (Milwaukee · Detroit · Cedar Rapids · Indianapolis CSV replays) run on ECS Fargate in private subnets behind four per-site internal NLBs — nothing internet-facing. The Indianapolis server carries the 5-Axis-Milling-CMX-441 bearing-degradation cycle live. Endpoint: opc.tcp://<nlb>:26543/UA/ManufacturingServer.

  2. Unmodified vendor image

    HighByte Intelligence Hub is industrial DataOps middleware that merges raw plant-floor signals into a Unified Namespace: one structured, live model of the plant. In this sample it represents the customer's OT data layer: whatever UNS or middleware a plant already runs can sit here, and ADT consumes it the same way (MCP/HTTPS). It runs the public Docker Hub image 4.5.3 on ECS Fargate with app state on Amazon EFS, and no custom build pipeline.

  3. One shared service port → SiteWise

    MCP + REST share :8885; the UI is on :45245. The pipeline writeSiteWise publishes 24 asset models and ~170 assets into AWS IoT SiteWise.

  4. Web access — VPC origins again

    The CloudFront distribution carries an AWS WAF web ACL and gates the UI paths with Cognito Authorization@Edge; it routes the default behavior to the UI origin and the machine paths /mcp* /i3x* /i3X* /data/* — which bypass edge auth and authenticate with a bearer token at the origin — to the shared origin :8885. The internal ALB accepts ingress only from the CloudFront VPC-origin security group.

  1. One scheduled Lambda → live data

    Amazon EventBridge rate(1 minute) invokes the simulation-orchestrator Lambda (container image, ARM64), which writes into Aurora Serverless v2 PostgreSQL — database erp_simulation, 30 tables across 12 schema files spanning orders, inventory, production, MES, and simulation bookkeeping. Each cycle advances a coherent factory story — orders progress, inventory draws down, production runs complete — so the data behaves like a real ERP, not a static fixture. That realism is the point: cross-system questions return live, changing answers, proving the engine queries systems at question time rather than replaying canned responses — and giving the self-learning loop real churn to learn from.

  2. Auth at the edge, not the ALB

    Cognito login happens at CloudFront via the SAR cloudfront-authorization-at-edge app, with AWS WAF at the edge. The ALB stays internal (:80, a CloudFront VPC origin) in front of Streamlit on ECS Fargate (:8501).

  3. Support without exposure

    The cleanup Lambda is wired to the dashboard Reset button; the seed Lambda runs at deploy time; the bastion EC2 is reachable only through SSM Session Manager — no inbound SSH, no public path to the database.
