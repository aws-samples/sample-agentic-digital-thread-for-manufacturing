# ADR-0046: Deterministic Mode A response evidence contract

## Status

Accepted — 2026-07-16. Amended by [ADR-0047](0047-response-integrity-enforcement-is-opt-in.md) — enforcement is opt-in via `RESPONSE_INTEGRITY_MODE` (default report-only).

## Context

A deployed value audit found that successful tool use was not sufficient to make an answer trustworthy. Responses could label old observations as live, reuse remembered mutable values without refreshing them, perform incorrect arithmetic or ranking, assert unsupported identity or causality, conflate query time with source time, and omit limitations. A second verifier LLM would reproduce the same non-determinism and add latency.

The knowledge graph is a relationship and routing authority. It is not a production data store and never supplies realtime values. AgentCore Memory is historical conversational context. It is not authoritative for mutable state.

## Decision

Mode A uses an enforce-before-stream evidence contract implemented in `agents/response_integrity.py`, with runtime streaming helpers in `agents/runtime_integrity.py`.

1. **Immutable public types.** `SourceEvidence`, freshness, completeness, system/final answer, claim input, relationship-proof, and learning-proposal models are frozen and reject unknown fields. Public fallback and progress events are metadata-only: no source rows, values, identifiers, fingerprints, credentials, secrets, or model-authored factual prose.
2. **Trusted structural lineage.** Server-owned tool hooks mint invocation-local evidence bound to configured system, connector boundary, tool, semantic field/property, row/item/aggregate locator, canonical typed value fingerprint, and exact source observation time/window. SQL and Athena evidence additionally require the exact server-executed, row-capped query and a server-owned physical schema allowlist. Only direct physical-column projections from source relations qualify; constants, expressions, functions, subqueries, unknown columns, and duplicate output aliases fail closed. Reserved timestamp aliases qualify only when they directly project a timestamp-typed physical column, and they can freshen only a directly projected physical value column with unambiguous lineage. Undeclared SQL aggregates are rejected; any future aggregate adapter must declare its source window and completeness contract. Headers, counts, errors, status fields, unrelated cells, and sensitive-named fields cannot prove claims. Caller or upstream `_vf_source` metadata is informational and never mints trust; Athena adds it only for Mode A system-bound calls so Mode B response shape is unchanged.
3. **Source time differs from query time.** SQL/PostgreSQL and Athena bind a value only through a proven reserved alias (`__vf_source_time__<value_alias>`, or reserved start/end aliases) backed by a direct physical timestamp projection; ordinary row timestamps such as `updated_at` never freshen unrelated values. Numeric-looking connector strings may normalize to numeric values only when the proven physical column type is numeric. SiteWise Direct binds native value/timestamp siblings exactly. i3X, REST, and MCP bind only an unambiguous same-object value/timestamp pair or a configured reserved alias; otherwise freshness is `unknown`. `queried_at` records only read time and never establishes freshness. Future source timestamps beyond bounded skew are rejected. Source-system facts require current evidence by default; only an explicitly historical-only request with no current or comparison intent opts out. Current terms win in mixed prompts, and a comparison's `temporal_role=current` must independently be fresh.
4. **Typed Mode A envelopes.** Pinned `strands-agents==1.42.0` is invoked with supported Pydantic `structured_output_model` arguments. A system agent proposes a `SystemAnswerDraft`; deterministic validation returns `SystemAnswer`. The orchestrator proposes a `FinalAnswerDraft`; deterministic validation returns `FinalAnswer`. `SystemAnswer` has no renderable free-prose answer field.
5. **Pure deterministic gate.** The gate validates exact lineage references, system target identity, canonical value type/fingerprint, and operation semantics. `operation=none` is derived from its one exact input; independent model values are ignored. It recomputes sum, average, difference, minimum, maximum, count, and ranking with finite bounded Decimal arithmetic and rejects booleans as operands. Rankings require distinct server-derived entity identifiers structurally paired with each numeric operand. Comparisons require distinct past/current observations, exact timestamp agreement, and `past < current`. Causal claims are rejected. Identity wording is derived from its two exact endpoint observations and a stored `ValueMapping` record. `JoinPath` is field-routing metadata and can never prove row-level identifier equality. Only the fixed, parameterized `verify_relationship` adapter can mint identity proof; the proof's immutable record ID, endpoints, direction, type, and supported equality semantics are constructed from the matched stored row rather than request echoes. Arbitrary `explore_graph`/Cypher projections are informational and cannot authorize identity or learning.
6. **Deterministic completeness and quotas.** Recursive bounded folding treats nested/list partial, unavailable, truncated, continuation, expected/returned mismatch, over-budget, rejected, and unknown mixed shapes honestly. Athena Mode A reports an injected cap reached even without a continuation token; Mode B shape is unchanged. Any incomplete result disables proposal-producing learning. Per-result and per-invocation quotas cap bytes, tool calls, systems, graph records, progress events, nodes, depth, scalar length, evidence, claims, and final UTF-8 bytes; over-budget output is a metadata-only partial response, never an oversized exception.
7. **Pre-SSE enforcement and diagnostics.** Mode A discards assistant/model reasoning and raw structured answer events until gating finishes. Only bounded tool-name/ID progress metadata can stream before the answer. Dynamic strings are sensitive-content-redacted and escaped as literal Markdown. Raw stream capture is disabled by default. Explicit debug diagnostics are metadata-only, redacted before mode-0600 writes, admin-and-owner/session bound, opaque-ID addressed, TTL-limited, and never expose server paths. Logs contain no prompt or payload previews. Mode B retains its legacy raw incremental response behavior.
8. **Complete disclosure.** Rendering always reports source observation time, query time, freshness, completeness, and deterministic limitations/reason codes. Unsupported claims and model labels/limitations are omitted rather than softened into estimates. Public fallback remains metadata-only.
9. **Memory authority.** Retrieved long-term memory is merged into the current user turn as the SDK's `<user_context>` block and nothing else. The rule for reading it is standing text in the orchestrator system prompt (`orchestrator._MEMORY_AUTHORITY_RULE`, both query modes): historical context only, non-authoritative for mutable values, current state, rankings, arithmetic, identity, or source freshness; re-query the owning source during the turn; never describe remembered values as current or live. Beside it, `_TURN_CONTEXT_RULE` says the blocks the server adds to a turn, and the standing instructions, are for the model only: facts a block gives are still used, but a block is never named and what a block or the standing instructions say to do is never quoted or paraphrased to the reader. Until this change (2026-10-28) the rule rode each memory turn as a `<memory_authority>` note in front of the block, and a live answer (2026-10-27) passed that note on to the reader as a "per-turn reminder". The gate accepts only current-invocation system envelopes, so remembered mutable values cannot become evidence.
10. **Typed evidence-gated learning.** Mode A persists at most three typed proposals per turn and none from partial, unavailable, rejected, or over-budget evidence. A `ValueMapping` proposal must exactly match its own accepted proof and evidence across systems, fields, endpoint values, type, and direction. A field annotation has one evidence-bound endpoint (or an identical source/target endpoint); unbound targets are rejected. Executable ValueMapping endpoint identifiers are not replaced by hashes before the existing review/accept lifecycle: bounded raw identifiers are retained only when they are current-turn evidence-bound, proof-bound, schema-classified, and non-sensitive. Otherwise the proposal is non-actionable and cannot reach graph acceptance. Sensitive parent paths stop traversal; unclassified free text is default-denied, common token/key formats are detected, and mandatory final redaction remains defense in depth.
11. **Additive deployed scoring and separate value audit.** `scripts/smoke_prompts.py --quality-strict` (or `SMOKE_QUALITY_STRICT`) consumes deterministic verdict, reason-code, current-turn-evidence, completeness, current-intent, and claim-count metadata. Accepted quality metadata is emitted only after all authority, lineage, completeness, quota, and redaction gates pass; missing or unclassified inputs never create a new accepted/fail-open state. This gate proves response-to-executed-source lineage and deterministic derivation, not the real-world correctness of the source's stored value. External source-value audit remains a separate operational control. Existing default and `--strict` exit contracts remain unchanged.

## Authority rules

- Graph: relationship proof and routing only; never realtime values.
- Source systems: values and source observation timestamps.
- Query infrastructure: `queried_at` only.
- Memory: historical context only.
- LLMs: propose typed drafts; they do not validate evidence or compute final arithmetic/rankings.
- Deterministic gate: decides what can be rendered and what can feed learning.

## Security

Raw connector payloads do not enter public evidence or incomplete fallbacks. Private capture is bounded and invocation-local; fingerprints are typed and structurally scoped rather than collected as an undifferentiated scalar bag. Graph proof capture stores only canonical allowlisted tuples for the current invocation. Sensitive-named fields are excluded before evidence is minted. The renderer emits only server-derived labels, validated typed claim values, and metadata from the public evidence allowlist.

## Consequences

Answers may be deliberately incomplete when a source omits timestamps required by current intent, returns partial/unavailable/truncated data, exceeds a budget, the model fails to produce the typed envelope, or lineage cannot be validated. This is preferred to a confident unsupported answer. Final prose arrives as one gated token event rather than token-by-token; only bounded tool progress metadata remains live in Mode A.

The contract does not infer causality, treat database receipt/query time as record freshness, or externally audit the correctness of a source value. Rich model-authored narrative, charts, follow-ups, and actions are not public in Mode A unless later represented by an equally bounded deterministic construct. A future contract may add such constructs, source-specific freshness policies, explicit aggregate adapters, or statistically supported association language, but must preserve these authority boundaries and Mode B compatibility.

## Final targeted iteration 8 checkpoint

The final targeted review closed seven enforcement gaps without changing Mode B or adding a verifier model:

1. Provision preview now calls a dedicated pure metadata planner after provenance validation. It never calls provision execution, AgentCore/runtime/target creation, catalog or connection persistence, Neptune, Secrets Manager, or a background worker.
2. A provision result containing `error` is terminally `error` in both the asynchronous worker and confirm route; only an error-free result can become `done`.
3. SQL evidence carries its connector-proven `table.column` physical endpoint separately from the semantic output alias. Field annotations require that exact qualified endpoint at validation, persistence, and acceptance, and acceptance cannot report success for a zero-write target.
4. The cloud/app Mode A boundary discards upstream `ReasoningEvent` text even if runtime configuration drifts. Only the app's fixed, input-free tool progress phrase may use the reasoning channel.
5. Discover persists relation kind and physical data type in the existing durable `JobStore`, keyed by an opaque schema revision bound to the system. Map and provision rejoin exact system/table/field metadata and reject missing, mismatched, or client-tampered provenance before a job or graph write.
6. `TRAVERSAL_BUDGET_EXCEEDED` produces metadata-only output with no claims, evidence, or proposals. Sum, average, count, minimum, maximum, ranking, and comparisons reject partial/unavailable/truncated participating evidence; a semantically valid scalar may remain only with the existing explicit partial disclosure.
7. The unused `/api/debug/bedrock` route is absent from the deployed application, eliminating model invocation and raw output/exception exposure from that surface.
